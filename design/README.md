# Круг — материалы для разработки лендинга

Выбран вариант **02 «Тёплое»**, мобильный и десктопный. Снимок согласованного дизайна: 20 октября 2026 года.

## Состав пакета

- `mobile.html` — самостоятельный HTML-макет, эталон на ширине **393 px**.
- `desktop.html` — самостоятельный HTML-макет, эталон на ширине **1440 px**.
- `copy.md` — тексты по блокам и микротексты демонстрационного интерфейса.
- `copy.txt` — текстовый экспорт мобильного макета.
- `tokens.css` — цвета и шрифты для переноса в `src/styles/tokens.css`.
- `adjustments.json` — точные CSS-переопределения, действовавшие в предпросмотре при экспорте каждого размера.
- `index.html` — просмотр двух макетов с переключением ширины.

HTML-файлы работают без сборки и внешних ресурсов. Откройте `index.html` в браузере. Для точного сравнения отдельных файлов задайте соответствующую ширину окна или viewport.

Это пакет дизайна, а не готовый Astro-проект. У HTML-макетов общие адаптивные стили и отдельные зафиксированные переопределения первого экрана; каждый файл является эталоном для своей ширины. Не подменяйте полноценную адаптивную вёрстку масштабированием всей страницы.

## Задача и стек

Лендинг представляет личную CRM «Круг»: контакты людей, контекст знакомства и заметки после разговоров. Основное действие — **«Открыть приложение»**.

- Astro, статическая сборка.
- Tailwind CSS 4.
- Отдельный проект `personal-crm-landing`, рядом с `personal-crm`.
- Сервер приложения и база данных лендингу не нужны.
- Версии Astro и пакетов уточнить по официальной документации при реализации и зафиксировать lockfile.
- Не добавлять регистрацию, уведомления, тарифы, отзывы, аналитику или неподтверждённые обещания.

## Порядок блоков и адаптация

| Блок | Мобильный, 393 px | Десктоп, 1440 px |
|---|---|---|
| Шапка | Логотип слева, ссылка в приложение справа | Дополнительно якорь «О продукте» |
| Первый экран | Заголовок, пояснение, CTA, подпись, пример CRM — вертикально | Текст слева, пример CRM справа |
| Проблема | Заголовок, абзац, бумажная записка, заключительный абзац | Текст слева, записка и подпись справа |
| Решение | Вводный текст, три последовательных шага | Заголовок и вводный текст в две колонки, шаги в три колонки |
| Выгоды | Три пункта вертикально | Три колонки под общим заголовком |
| Финальное действие | Арочный блок, заголовок, пояснение, CTA | Широкий центрированный арочный блок |
| Подвал | Логотип и короткая подпись | Те же элементы по краям |

В макетах разделение мобильной и десктопной композиций задано на 700 px. При реализации проверьте промежуточные ширины 768 и 1024 px: если три колонки становятся тесными, вводите промежуточную сетку. Приоритет — точное соответствие эталонам 393/1440 px и отсутствие горизонтальной прокрутки между ними.

## Визуальная система

Характер: спокойный, личный, тёплый. Кремовая бумага, терракотовые акценты, мягкие формы, тонкие разделители.

| Роль | Значение |
|---|---|
| Фон страницы | `#F5EFE4` |
| Поверхность карточки CRM | `#FFFCF6` |
| Основной текст | `#3D3B2F` |
| Вторичный текст | `#817B6E` |
| Акцент / CTA | `#A94D33` |
| Текст на CTA | `#FFFAF0` |
| Разделители | `#DED5C5` |
| Мягкая подложка | `#EEE6D6` |
| Круг за интерфейсом | `#DFCEB1` |
| Декоративный стикер | `#E6BF75` |
| Бумажная записка | `#E9D8B5` |
| Финальный арочный блок | `#E9DFCD` |

Большие заголовки: **Georgia**, затем Times New Roman и serif; вес 400. Выделенная часть — курсив и терракотовый цвет. Интерфейс и обычный текст: системный sans-serif (`-apple-system`, BlinkMacSystemFont, Segoe UI, sans-serif). Внешние шрифты не загружать.

Базовые размеры до пользовательских переопределений:

- H1: 52 px на мобильном; `clamp(48px, 5.8vw, 84px)` на десктопе; интерлиньяж 1.02.
- Заголовки секций: 36 px на мобильном; 50–60 px на десктопе. Финальный заголовок: 35/64 px.
- Основной вводный текст: 14 px на мобильном; 16–17 px на десктопе, интерлиньяж 1.65–1.8.
- Мобильные поля секций: 24 px, вертикальные отступы секций: 48 px.
- Десктопные поля: 6%, вертикальные отступы: 80 px, промежуток между тремя колонками: 44 px.
- Кнопки округлые: радиус 50 px; точные размеры первого экрана сверять с `adjustments.json`.
- Демонстрационная карточка CRM повёрнута на 3°, стикер на −6°, бумажная записка на −2°.

Графика сделана средствами HTML/CSS: кольцо логотипа, круг за карточкой, стикер, записка и арочный блок. Внешние фотографии и платные ассеты не нужны. Пример CRM — декоративная иллюстрация с вымышленными контактами, не работающий интерфейс и не скриншот реальных данных.

## Перенос в Astro и Tailwind CSS 4

Рекомендуемая структура:

```text
src/
  pages/index.astro
  components/Header.astro
  components/Hero.astro
  components/ContactPreview.astro
  components/Problem.astro
  components/HowItWorks.astro
  components/Benefits.astro
  components/FinalCTA.astro
  components/Footer.astro
  styles/global.css
  styles/tokens.css
```

Подключить Tailwind CSS 4 через официальный плагин `@tailwindcss/vite` в Astro, в `global.css` использовать `@import "tailwindcss";` и импорт локальных токенов. Не использовать устаревшие директивы Tailwind 3 или добавлять конфигурацию v3 по шаблону.

Сохранить тексты из `copy.md`. Общие цвета и шрифты брать из `tokens.css`; сложную геометрию и наклоны допустимо описать обычным CSS. Панель ползунков, выбор четырёх стилей, iframe и оболочка предпросмотра **не входят в итоговый лендинг**.

Использовать семантические `header`, `main`, `section`, `footer`, один H1 и последовательные H2/H3. Добавить видимый фокус для клавиатуры, скрыть чисто декоративные значки от скринридера. Проверить контраст текста и кликабельность CTA; небольшие декоративные подписи не должны содержать единственную копию важной информации.

## Ссылки в приложение

Во всех эталонах CTA пока ведут на **`http://127.0.0.1:3000`**, локальную CRM. Это не production-адрес.

Перед публикацией заменить все CTA одной общей настройкой на `https://app.<домен>`, когда домен будет определён. Не публиковать localhost-ссылки. Якорь «О продукте» ведёт к `#why`. Сохранить единый текст CTA «Открыть приложение».

## Проверка результата

1. Собрать статический сайт и проверить отсутствие ошибок сборки.
2. Снять скриншоты на 393 и 1440 px; сравнить с соответствующими HTML-эталонами.
3. Проверить порядок всех пяти основных блоков и точность текстов.
4. Проверить промежуточные ширины, отсутствие обрезанного текста и горизонтальной прокрутки.
5. Проверить все CTA, якорь и навигацию клавиатурой.
6. Убедиться, что нет обращений к CRM API, секретов, реальных контактных данных или редактора дизайна в production.

При расхождении приблизительных значений README с HTML приоритет у соответствующего HTML-эталона и его зафиксированных настроек. Изменения текстов или выбранного визуального направления согласовывать отдельно.
